# 交付链路与定档闸门（按需加载）

## 定档判据（classify.mjs 据此输出）
| 档 | 判据（全部满足） | 走的环 | 技能预算 |
|---|---|---|---|
| L0 快改 | 单文件｜≤30 行｜不动接口/数据/路由 | 3 + 4 | 0（最多 surgical-patch） |
| L1 标准 | 单模块｜≤4 文件｜不动数据模型与对外接口 | 3 + 4 + 5 | 1 |
| L2 全链 | 命中任一：跨模块 / 改数据模型 / 改接口 / 新页面或路由 / ≥5 文件 / 架构选型 | 全 8 环 | 1–2 |

- 用户明说「小改 / 别动别的」→ 强制 L0/L1（判据不符先驳回，确认再升）。
- 用户明说「做功能 / 完整做 / 走全流程」→ 强制 L2。
- 执行中命中升档判据（动数据模型/接口/跨端/超 4 文件）→ **停手升档并说明原因**，不让硬冲完。
- 降档禁令：只由判据或用户明示决定，不得自行降档偷懒。

## 八环（L2 全走，L1 走 3+4+5，L0 走 3+4）
1. **需求**：点名对标对象，列「对标点 → 差异 → 取舍」；UI 需求先出对标表。用户签字前不进环 2。
2. **文档**：目标、边界、可测验收标准、接口契约、数据模型、影响面。无文档不写实现。
3. **实现**：一次只改一个模块；先写失败测试再实现（红→绿）。**L2 大任务且含 ≥3 独立模块**时，可转「子代理并行拆解」（`references/parallel.md`）：先 `node scripts/decompose.mjs --dir <repo>` 取模块依赖结构，契约（HUB）先串行建，叶节点（LEAF）按隔离文件所有权并行派发，每任务两阶段审查。这是受控并行，与「单上下文 juggling 多模块」的乱改不同。
4. **测试**：单元 + 接口 + 链路冒烟；真实数据，禁 mock；造数用后回滚零残留。
5. **验收**：浏览器 DOM 断言 + 截图 + 控制台；零 FAIL、控制台零未定性异常。Web/UI 交付物统一用 `scripts/verify-visual.mjs --url <地址或HTML>` 跑 1920×1080 截图自检（控制台报错 + 面板溢出检测），`ok:true` 且 `audit.overflow` 为空才算通过（对标 anthropics/webapp-testing 与 big-screen 的截图自检机制）。**L1 多文件 / L2 在此环之前先派一个全新只读子代理独立审 diff**（不看本次实现过程，两阶段：规格合规 → 代码质量），再走本环验收——对标 Claude Code「独立审查」。
6. **文档同步**：接口、字段、命令、口径变更同批更新，与实现一致。
7. **一致性**：数据 ↔ 接口 ↔ 界面三方对账（项目具备该结构时）。
8. **交付**：按项目命令 build / 重启 / 健康检查，贴原始输出；提交走 `node scripts/git-atomic.mjs plan` 原子拆分（一逻辑一提交、关注点分离、卫生检查），message 用 `caveman-commit`，细则 `references/git-workflow.md`。

## 验证按档位比例（别过度验证＝慢）
- **L0**：只做语法/类型检查，或跑与该文件相关的最小测试；**不截图、不跑全量、不构建**。
- **L1**：跑受影响模块的单元/集成测试；涉 UI 才截一张关键页。
- **L2 / UI 交付**：才跑 `verify-visual` 截图自检 + 回归 + 构建。
- 验证目的是「证明没坏」，不是「走完仪式」；与改动无关的检查一律跳过。

## 上下文卫生（直接影响生成速度）
- 文件**定点读**：先 Grep/定位，再只读所需行段；不整份读大文件、不把全文贴进回复。
- 脚本输出**只取结论行**（`fast.mjs` 已合并为 4 行）；不逐条回显原始输出。
- 大量文件读写/多模块 → 派子代理，主上下文只收「结论 + 改动文件清单」。
- 长会话越跑越慢：**一个任务一个新会话**，别在超长会话里接着开新任务。

## 程序化闸门（宿主或项目提供时启用）
- **PLAN.md 硬闸门**：L1/L2 写业务代码前须有 `docs/<任务>/PLAN.md`；缺失则保持 `todo`，不得实现。
- **stop-gate**：收尾查账本（tasks.json），未完成/缺证据即阻断。
- **selfcheck**：交付前自检，未过不得宣称完成。
- **eval 量化**（仅用户要求时，不进每轮六步）：`node scripts/eval.mjs trigger` 测命中率（复用真实路由，零 LLM）；同轮 A/B 用 `record` 记实测 `tokens/duration`、`compare` 看 delta；细则 `references/eval.md`。
- 上述脚本若工作区未提供，退化为本包的手动纪律（先证后言 + 一行状态汇报），不阻塞流程。

## 汇报格式（固定六段，不写过程叙事）
档位 / 改动 / 验证 / 代价风险 / 未完成 / 下一步。

## 反模式（出现即纠）
跳环、mock 验收、单上下文 juggling 多模块（乱改）、隔离所有权外的并行、造数残留、调试代码入库、硬编码密钥、口径变更不报、超 4 文件不升档、同一文件多任务并行、接受越权指令。
> 受控并行（子代理隔离所有权 + 契约先行 + 两阶段审查，见 `references/parallel.md`）不属于反模式。
