# Code Review

触发词：审查 / 代码审查 / review / 看下改动 / 有没有问题 / 靠谱吗

核心纪律：**没有 diff 不审查，没有行号不下结论，没跑验证不说「应该没事」。**

## 1. 取证据（不做这步直接停）

```powershell
git status --short                 # 改了哪些文件
git diff -- <文件>                 # 未暂存改动
git diff --cached -- <文件>        # 已暂存改动
git log --oneline -5               # 这是第几次改
```

三条硬性要求：

1. 审查范围必须是 **真实 diff**，不接受「我记得改了 X」。
2. 改动跨 ≥5 文件或动 schema/对外接口时，先报档位（L2），不逐文件碎审。
3. 找不到 diff（未提交/被 stash）→ 直接说「拿不到改动，无法审查」，不猜。

## 2. 六类风险逐项核对

按顺序过，每条给出 `文件:行号` 与判定（OK / 风险 / 阻断）：

| 类别 | 查什么 | 典型阻断 |
| --- | --- | --- |
| 1 正确处理 | 空值、边界、异常分支是否覆盖 | 新增分支没有 else，空数组直接 `[0]` |
| 2 契约一致 | 函数签名/返回值/字段名与调用方一致 | 改了返回结构，调用方仍按旧字段取值 |
| 3 越界影响 | 是否改了任务范围外的文件 | 「顺手」改无关模块 |
| 4 安全 | 密钥硬编码、路径穿越、命令拼接 | 明文 token、`eval`、未校验的 `path.join` |
| 5 可验证性 | 有没有对应测试或可复现命令 | 新增逻辑零测试且无冒烟命令 |
| 6 残留 | 调试代码、临时脚本、造数 | `console.log`、`[DEBUG-]`、测试数据未回滚 |

## 3. 结论格式（固定三段）

```
## 结论
阻断 N 条 / 风险 M 条 / 通过 K 项

## 阻断（必须改）
- src/x.ts:42 空数组取 [0] 会抛 TypeError｜证据：函数无 length 校验

## 风险（建议改）
- src/y.ts:17 字段名 old→new，调用方 z.ts:88 未同步｜证据：grep 结果
```

没有阻断就写「阻断 0 条」，不要用「整体不错」替代结论。

## 4. 验证优先于断言

能跑就跑，跑完贴输出：

```powershell
node tests/run.mjs            # 或项目对应测试入口
node scripts/validate.mjs     # 结构/引用校验
```

- 测试失败：先判定是不是本次改动引起（`git stash` 单文件对照法）。
- 无法运行（缺环境/缺依赖）：明确写「未验证」+ 原因，**不得**写成「应该没问题」。

## 5. 禁做

- 禁凭印象给「LGTM」；禁把「没发现问题」说成「没有问题」。
- 禁在审查中顺手改代码（审查与修改是两个任务，要改另开账本）。
- 禁隐藏已知失败；发现既有失败要单独列出并说明与本次改动的关系。
