# 高可信调研

目标不是"找到一些相关文字"，而是**让结论站得住**：每条关键判断都能指到原始出处，且强弱分明。

## 1. 先定调研问题

一句话写下这次要回答什么，以及**什么证据能改变结论**。问题太宽就先收窄成 2–3 个可回答的子问题。写下来给用户看一眼再开跑——跑偏的代价比多问一句大。

## 2. 来源分级（每次都要标）

| 级 | 来源 | 用法 |
|---|---|---|
| A | 官方文档、规格原文、源码、标准、财报/年报、法条 | 可直接支撑结论 |
| B | 一手实测、当事人原始陈述、同行评审论文 | 可支撑，注明条件 |
| C | 二手报道、技术博客、教程 | 只能当线索，须回溯到 A/B |
| D | 论坛、问答、AI 摘要、聚合站 | 不支撑结论，只用来找线索 |

**只用 A/B 定结论。** 撞到 C/D 就顺着它去找上游 A/B；找不到上游，就把这条降级为"听说"。

## 3. 取证纪律

- 每个结论后面挂**可点的原始链接**，不是二手页。
- 区分**事实**与**推断**，分别标。推断要写出依据和它可能错在哪。
- 记下**时间**：文档有版本号和日期，API 有废弃公告，价格有有效期。没有日期的说法一律当旧闻处理。
- 两个来源打架，不要投票取多数，去找**为什么打架**（版本不同？地区不同？口径不同？）。
- 拿不到就说拿不到。**不许用常识补空洞**，也不许把搜索摘要当成读过原文。

## 4. 交付形状

一页，按这个顺序：

1. **一句话答案** —— 先给结论。
2. **依据** —— 3–6 条，每条带出处链接与等级。
3. **不确定的地方** —— 明确列出还没验证的部分，以及它会怎么改变结论。
4. **下一步** —— 要坐实还差什么（找谁、读哪份文档、跑什么实验）。

需要给用户看时写成 `research-<主题>.md` 放工作区，不要把长篇倒进对话。

## 不要做

- 不要为了凑满篇幅去堆 C/D 级来源。
- 不要把"没搜到"说成"不存在"。
- 不要在没读过原文的情况下引用它的观点。
