# Skill Audit

触发词：检查技能 / 审查 SKILL.md / skill 审计 / 技能质量 / 缺触发词吗 / 有没有验证步骤

核心纪律：**逐条给出文件名:行号与判定（缺失 / 完整），没有证据不下结论。**

## 1. 输入

1. 用户指明目标文件（如 `skills/foo/SKILL.md`）；未指明则默认扫描 `skills/**/SKILL.md`。
2. 读取目标文件全文，记下总行数与章节结构。

## 2. 审查项（按顺序逐条核对）

| 类别 | 查什么 | 典型缺失 |
| --- | --- | --- |
| 1 触发词 | 是否有明确的触发词行或 description 中列出的触发场景 | 只有 description 无触发词行，或 description 为空 |
| 2 验证步骤 | 是否存在可执行的验证/测试/检查命令 | 零命令、只说「跑测试」不给命令 |
| 3 门禁 | 验证不通过时是否有阻断动作（停止、标记未完成） | 验证失败后无后续处理 |
| 4 禁做 | 是否列出至少 1 条禁止项 | 无禁止清单，只写正向步骤 |
| 5 体积 | 文件 ≤8KB（单技能限制） | 超限未拆 references/ |

每条给出 `文件:行号` 与判定（完整 / 缺失 / 部分），无内容直接写缺失。

## 3. 结论格式（固定三段）

```
## 结论
缺失 N 项 / 完整 M 项 / 部分 K 项

## 缺失（必须补）
- skills/foo/SKILL.md:3 description 未写触发词
- skills/foo/SKILL.md:-- 无验证命令

## 部分（建议补）
- skills/foo/SKILL.md:12 验证步骤存在但无门禁
```

没有缺失就写「缺失 0 项」，不要用「整体合格」替代结论。

## 4. 验证优先

- 能跑就跑：对每个目标文件执行 `wc -c` 确认体积，`grep -n "验证\|测试\|门禁"` 确认有命令。
- 跑完贴输出，不凭印象说「应该有」。
- 无法确认时写「未验证 + 原因」，**不得**写成「应该没问题」。

## 5. 禁做

- 禁在审查中顺手改文件；审查与修改是两个任务，要改另开账本。
- 禁把「没发现问题」说成「没有问题」。
- 禁跳过缺失项直接给通过结论。
