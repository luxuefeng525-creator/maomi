# /ai-plan · 开发前文档

L1/L2 在写业务代码前必须先落文档。**没有 `PLAN.md` 不许动手。**

## 1 写文件

路径固定：`docs/<slug>/PLAN.md`（`slug` 用短横线英文，与账本目录同名）

```powershell
# 建目录（示例 slug = export-btn）
New-Item -ItemType Directory -Force -Path docs/export-btn
```

## 2 PLAN.md 必须包含 7 段

| 段 | 写什么 | 判据 |
| --- | --- | --- |
| 1 目标 | 一句话说清做成什么样 | 能被第三个人读懂 |
| 2 边界 | 动什么、不动什么 | 明确列出「不做」 |
| 3 实测约束 | 已取证的限制（体积/阈值/依赖/既有实现） | 每条带数字或路径 |
| 4 取舍 | 有分叉的地方怎么选、为什么 | 不用「看情况」 |
| 5 影响面 | 逐文件列出改什么 | 文件路径逐个列 |
| 6 验收标准 | 可执行、可判定的条目 | 每条能跑命令验证 |
| 7 回滚 | 怎么退回 | 具体命令或删除范围 |

## 3 建账本

```powershell
node {{PKG_ROOT}}/scripts/agent.mjs plan --task "<目标>" --slug <slug> --files <预计文件数>
```

`--files` 决定档位：≤30 行单文件 → L0；≤4 文件单端 → L1；≥5 或跨端 → L2。

## 4 与硬闸门的关系

`node {{PKG_ROOT}}/scripts/agent.mjs run --slug <slug>` 会在**进入实现步前**校验 `docs/<slug>/PLAN.md`：

- 缺失 → 打印 `GATE BLOCK <ID> | 缺 docs/<slug>/PLAN.md，先出文档再实现`，停在该步
- 该步保持 `todo`，**补完文档重跑同一条命令即可续做**

在 Trae 对话里不经过 `agent.mjs run` 时，靠自觉执行本命令，不得跳过。

## 5 写完要做

1. 把 PLAN.md 的 7 段逐条念给用户确认（尤其「边界」和「验收标准」）
2. 用户点头 → 才开始实现；被改动 → 先改 PLAN 再改代码
3. L2 还要补：对标表（3 家真实页面）、接口契约、数据模型、影响面

## 禁止

- 先写代码后补文档
- PLAN.md 只写「实现 X 功能」一句话就开工
- 验收标准写成「体验良好」「基本可用」这类不可判定表述
