# 长任务与超时（按需加载）

单次工具调用有上限（常见 2 分钟），`npm i`、`build`、`playwright install`、多步 E2E、批量跑测试都可能超时。**超时不是失败，丢进度才是失败。**

## 1 先落检查点，再开长活

```bash
node scripts/checkpoint.mjs start "<任务>" --steps "调研|契约|实现|测试|验收"
node scripts/checkpoint.mjs done "实现" --note "改了 auth/login.ts"
node scripts/checkpoint.mjs status        # 随时看进度
node scripts/checkpoint.mjs resume        # 新会话续跑：上次做到哪、下一步
```
每完成一个步骤就 `done` 一次；长命令**前**先 `done` 上一个步骤，超时后从下一步续。

## 2 长命令放后台 + 轮询（不要 sleep 死等）

- 预计 >2 分钟的命令（安装、构建、全量测试）→ 后台执行，定期读输出。
- 后台进程失败要看退出码与 stderr，别当成「还在跑」。
- 不要用 `sleep` 轮询；用「检查进程/日志」的方式判断完成。

## 3 单步超时 + 有限重试

- 每个外部调用设超时（脚本已内建，如 `browser.mjs --timeout`）。
- 网络/安装类可重试，**指数退避、最多 3 次**；同一命令连续失败 2 次就停手查因，不要无脑重跑。
- 重试前先 `resume`，确认不会重复已完成的工作。

## 4 拆掉「一次做完」的执念

- 一个大任务拆成可独立验收的小步（每步 5–20 分钟可完成）。
- ≥3 个独立模块 → 子代理并行（`references/parallel.md`），总时长和主上下文都下降。
- 需要跨会话接力时写 `HANDOFF.md`：当前状态、已改文件、下一步、坑。

## 5 红线

- 禁「超时了就整任务重跑」——先 `resume` 看做到哪。
- 禁把检查点写在会被提交的业务目录里造成脏 diff——默认 `.ai-workflow/` 应被忽略。
- 禁为了快跳过检查点；检查点本身就是「不丢进度」的保险。
- 禁无限重试/死等；有限次失败后必须停手报告。
