# 上下文工程（按需加载 · 省 token + 提准确度）

模型慢/答偏，多数不是能力问题，是**上下文喂错了**：要么整份读大文件把窗口塞满，要么只看到片段丢了全局。本文只讲两件事：先看地图，再定点读。

## 1 先出「仓库地图」，别整份读

```bash
node scripts/context.mjs --dir <repo>            # 默认 4000 字符预算
node scripts/context.mjs --dir <repo> --budget 8000
node scripts/context.mjs --dir <repo> --json     # 机器可读
```

输出是「文件路径 (行数) :: 顶层符号」的有界清单（自动跳过 `node_modules/dist/.git` 等）。作用：
- 让你**先知道有什么**（有哪些模块、类、函数），再决定读哪几个；
- 避免「一上来把 20 个文件全读一遍」——那是上下文爆炸和答偏的主因；
- 对标 Aider repo-map / Cursor 代码库索引的轻量替代，零依赖、不建向量库。

**用法**：先在输出里定位目标文件 → 只 `Grep` 关键词或 `Read` 该文件的相关行段，不整份载入。

## 2 定点读（targeted read）

- 找定义：`Grep "function foo|class Foo"` → 拿到行号 → `Read offset/limit` 只读附近。
- 找调用：`Grep "foo("` → 看谁在用、签名怎么传。
- 大文件（>500 行）**永远不要整份 Read**，先读前 80 行取结构，再定点。

## 3 上下文预算纪律

| 场景 | 做法 |
|---|---|
| 小改（单文件） | 直接读该文件相关行，不跑地图 |
| 中等（3–10 文件） | 跑一次 `context.mjs`，挑 3–5 个关键文件读 |
| 大任务（>10 文件 / 多模块） | `context.mjs` + 子代理：每个子代理只拿自己的文件，主上下文只收结论 |

## 4 与子代理的关系

子代理的价值就是**上下文隔离**：把「读 20 个文件」的脏活丢给子代理，它回一段摘要，主上下文保持干净。派发时给**最小上下文**（任务 + 文件清单 + 契约 + 验收），不要把整段历史塞过去（见 `references/parallel.md`）。

## 5 红线

- 禁「整份读大文件再思考」——先地图、再定点；
- 禁把脚本/工具的原始长输出整段贴回上下文——只取结论行；
- 禁在超长会话里开新任务——**一个任务一个新会话**。
