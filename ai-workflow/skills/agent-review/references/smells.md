# 审查基线（标准轴）

两条轴**分开跑、分开报**，不许合并成一句"整体还行"：

- **规范轴**（Standards）：违反了哪些已写下的规则。先看仓库里有没有 `CONTRIBUTING.md`、`CODING_STANDARDS.md`、lint 配置、ADR —— 有的**优先用它的**，下表只是仓库没写时的兜底基线。
- **规格轴**（Spec）：是否满足这次的需求，有没有做了没被要求的事。规格轴不引用任何代码规范，只看"要求的做了没有、多做的删不删"。

## 兜底气味表（Fowler 式，仓库没立规矩时用）

每条只算**线索**，不是判决。标 `path:line`，说清它是怎么坏的，再给修法。

| 气味 | 长什么样 |
|---|---|
| 过长函数 | 一件事读不到底，要靠注释分段 |
| 过长参数表 | 四个以上参数，或布尔 flag 撑起分支 |
| 重复代码 | 同一段判断在两个以上地方抄 |
| 特性依恋 | 方法狂用别的对象的数据，说明它站错了类 |
| 数据泥团 | 三四个字段总是一起出现，该合成一个类型 |
| 基本类型偏执 | 用 string/int 表达该有自己类型的概念（金额、ID、状态） |
| 发散式变化 | 一个改动要同时改好几个不相干的文件 |
| 霰弹式修改 | 一个逻辑变更散落在多处小改 |
| 分支爆炸 | switch/if 链按类型长，加一种类型就要回来改 |
| 注释当遮羞布 | 注释在解释"这行为什么这么怪" |
| 死代码 | 没人调用的函数、永不成立的分支、注释掉的块 |
| 投机泛化 | 只有一个实现的接口、从没用过的参数 |

## 硬规则（不看语言，永远查）

- 边界与空值：空列表、空字符串、0、null、超大值、负值。
- 错误处理：吞异常、只记日志不处理、抛了不接、错误信息里没上下文。
- 并发与幂等：共享状态、重复提交、重试是否安全。
- 可回滚：这次改动能不能单独撤回而不牵连别的。
- 测试是否**真能失败**：把实现改坏，测试会红吗？不会红就是同义反复（见 `tdd` 反模式）。
- 密钥与个人信息：有没有硬编码、有没有进日志。

## 报法

- 每条：`path:line — 气味/规则 — 为什么坏 — 怎么修`。
- 按**严重度**排：会丢数据的 → 会错的 → 会烂的 → 风格。
- 没有 `path:line` 的结论一律无效。
- 不确定写"不确定，需要 X 才能判断"，不要猜。
