# 架构

## 分层

```text
Agent 人格（agents/orchestrator.md）
        │ 负责身份、红线、第一动作
        ▼
调度技能（skills/project-orchestrator）
        │ 负责定档、8 环、路由、停点
        ├──▶ 记忆技能（skills/project-memory）  证据与结论留档
        └──▶ UI 技能（skills/ui-ux-benchmark） 界面对标与验收
                        │
                        ▼
              脚本：validate / memory / ui-audit / install
```

人格文件与技能分离：人格只在支持 agents 目录的工具生效；技能在任何遵循 Agent Skills 约定的工具都能加载。

## 关键决策

| 决策 | 理由 | 代价 |
| --- | --- | --- |
| 核心规则与项目配置分离（`.agent/project.md`） | 技能可跨项目复用，项目事实可替换 | 新项目要写一份配置，否则靠探测 |
| 单技能 ≤8KB，细节拆 references | 控制上下文成本，主文件可快速读完 | 需要多跳一次文件 |
| 记忆不用向量库 | 数万字符规模关键词检索够用；避免索引漂移与常驻服务 | 同义改写可能查不到 |
| 记忆只追加、失效不删除 | 可回查、可回滚，避免改写历史 | 文件体积线性增长，需要定期合并 |
| 门禁用脚本而不是形容词 | 可 CI、可复现、不依赖模型自觉 | 只能覆盖可判定项 |
| UI 不做审美评分 | 审美不可验收，容易产出模板感 | 需要人工签收 |

## 数据流

1. 任务开始：读 `.agent/project.md` 与记忆索引 → 定档 → 写 `tasks.json`。
2. 每环完成：命令输出与截图作为证据；结论写入记忆日志。
3. 任务结束：账本 `status=done` + `evidence`；记忆写一条 decision 或 pitfall。
4. 失败或中断：`HANDOFF.md` 四项交接，下次从账本恢复。

## 兼容边界

- 依赖 Node ≥18，无第三方依赖。
- 路径解析以当前工作目录为基准，不写绝对路径。
- 工具名、目录名不在技能正文硬编码；需要时由项目配置提供。
